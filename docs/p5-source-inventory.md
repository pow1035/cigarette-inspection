## 项目报告提供的业务背景

`05_项目文档与汇报/4、张烟--卷烟机烟支外观在线检测系统的研发--技术报告.docx` 记录了传统 HALCON/BLOB 路线，以及烟支刺破、夹末、黄斑、长短、污渍、水松纸泡皱、夹末、长短、双层水松纸、错牙等缺陷范围。它可支持术语和业务场景整理，但报告中的历史性能描述不能替代当前模型验收。

报告还说明原系统参数多、调整难、维保难，因此 P7 应优先减少无依据参数、提供模型版本/阈值/效果证据和故障诊断，而不是把全部传统参数原样搬到深度学习界面。

## 只能选择性使用

- `推理源码_expert_test` 可借鉴导出、图像/视频推理和 benchmark 结构，但混有 TensorRT 8、640 输入、COCO 类别和个人绝对路径。
- 历史 `.engine` 与 GPU/TensorRT 版本绑定，不能作为当前部署包；必须从已记录哈希的 ONNX 在目标环境重建。
- `yolo26s.pt`、`yolo26.zip` 和 `mydata.yaml` 属于通用 COCO/Ultralytics 资料，不是烟支训练配置或烟支效果证据。
- 传统算法规则可以生成候选 ROI 或后处理假设，不能自动生成训练真值。

## 当前缺口和风险

1. 没有烟支 YOLO TXT、COCO JSON、VOC XML 或其他人工框标签。
2. 没有原始训练/验证划分、训练日志、自定义训练 YAML、指标或训练代码。
3. 116 图跨越多个日期和文件名前缀，可能来自不同机位；划分前不能假设独立同分布。
4. `wuzi`、`jietou` 在现有 Qt 参数结构中没有中文业务映射和逐类阈值。
5. ONNX 元数据和部分原型资料包含 AGPL/研究用途提示；商业许可和第三方代码合规必须单独确认。
6. 数据来源于项目资料，但尚无正式授权清单、客户脱敏结论和训练/测试独立性证明。

## 使用顺序

1. 先由审计工具冻结文件哈希、重复关系、尺寸、来源组和授权状态。
2. 历史框和 P4 输出仅进入 preannotated 层。
3. 人工依据 `p5-labeling-guide.md` 修订并将状态改为 reviewed 后，才允许计算准确率。
4. 首批 20-30 图试点通过一致性复核后，再扩展到 113 个唯一样本。
5. 只有评估报告证明后处理不足，才进入模型重新训练或微调。
