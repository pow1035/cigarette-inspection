# 项目需求基线

版本：2026-07-10 P0 基线

## 目标

开发一套用于烟厂烟支外观在线检测的 Windows Qt/C++ 上位机。系统接收工业相机图像和卷烟机同步信号，以深度学习为主要检测方式，形成“采集、检测、判定、显示、保存、统计、剔除”的可验证闭环。

## 当前事实

- `01_上位机_QT_新版_CigVision/源码` 已有 UI、参数、相机初始化、相机回调、图像队列和 IO 读取骨架，但生产闭环尚未接通。
- `02_上位机_QT_老版_传统算法` 有较完整的传统算法处理、NG 编号、保存和剔除实现，可用于理解时序和业务规则。
- `03_深度学习模型与TensorRT` 有独立的 YOLO/TensorRT C++ 推理代码、ONNX/engine/PT 模型和部署资料，尚未接入新版 Qt 工程。
- 当前事实来自源码和文件检查；尚无本轮 Windows 编译、GPU 推理、相机或 IO 运行证据。

## 功能需求

| ID | 需求 | 验收方向 |
| --- | --- | --- |
| FR-01 | 读取并校验系统、品牌、相机、模型和剔除参数 | 缺失/非法参数有明确错误，不能静默带病运行 |
| FR-02 | 为每帧生成稳定的工位、相机、烟支编号和时间信息 | 从采集到保存/剔除可追踪同一帧 |
| FR-03 | 通过统一检测器接口调用检测算法 | 上位机运行层不依赖具体 YOLO 或 Halcon 实现细节 |
| FR-04 | 使用 TensorRT 模型输出缺陷框、类别和置信度 | 离线样例可重复推理，结果结构稳定 |
| FR-05 | 将模型类别和阈值规则转换为 OK/NG 及缺陷类型 | 类别表、阈值、禁用类别均可配置且可追溯 |
| FR-06 | 根据烟支编号、工位延迟和安全条件生成剔除命令 | 模拟模式可核对编号；真实 IO 默认关闭 |
| FR-07 | 按日期、相机、缺陷类型保存必要图像和元数据 | 保存失败有日志，不阻塞检测主链路 |
| FR-08 | UI 显示运行状态、图像、检测结果、统计和错误 | UI 更新与后台线程隔离，停止后状态一致 |
| FR-09 | 支持可控启动、停止和异常恢复 | 重复启停不残留工作线程，不继续产生剔除命令 |
| FR-10 | 支持离线图片回放，不连接相机和 IO 也能验证检测链路 | 固定输入可生成固定格式结果和证据 |
| FR-11 | 保留传统算法接入边界 | 是否实现生产兜底由业务确认，不阻塞深度学习主线 |
| FR-12 | 记录关键运行日志和性能数据 | 可定位相机、队列、推理、保存和剔除阶段的问题 |

## 非功能需求

| ID | 需求 | 当前约束 |
| --- | --- | --- |
| NFR-01 | 安全 | 无显式联调许可时不写真实剔除 IO |
| NFR-02 | 时序 | 单帧推理时延、端到端时延和允许队列深度待现场节拍确认 |
| NFR-03 | 稳定性 | 目标连续运行时长待确认；最终需做长时间运行和资源增长检查 |
| NFR-04 | 可维护性 | 新业务逻辑进入新版工程；老版工程保持参考性质 |
| NFR-05 | 可复现性 | Windows 工具链、依赖版本、模型哈希和配置均需记录 |
| NFR-06 | 数据保密 | 仓库保持私有；大安装包、现场数据和敏感资料不进入普通 Git 历史 |

## 范围

本项目范围包含新版上位机、深度学习推理接入、离线回放、检测结果处理、图像保存、统计、模拟剔除、真实相机/IO 联调、日志和部署说明。

本阶段不包含模型重新训练、数据标注平台、硬件 PCB 改版、卷烟机机械结构改造，也不承诺未定义的检测准确率或生产节拍。

## 保守假设

- 最终部署环境为 Windows x64，Qt 5.9.9、Visual Studio、Halcon、海康 MVS、Advantech DAQNavi、CUDA/TensorRT/OpenCV 的确切兼容组合将在 P1 固化。
- 新版 `CigVision` 是产品主线；老版 `testQT` 不继续扩展功能。
- 深度学习是主要检测路线；传统算法是否作为现场可切换兜底由 OD-05 决定。
- 在真实硬件验证前，剔除链路只使用模拟输出和日志证据。
